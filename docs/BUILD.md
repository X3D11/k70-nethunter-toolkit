# 构建与验证方法

**简体中文** | [English](BUILD.en.md)

本公开包不是完整的可复现内核构建环境：不包含设备原始配置、厂商 ABI 数据、模块签名密钥、完整工具链、固件、内核源树或最终镜像。

1. 保存本机 boot/init_boot/vendor_boot 等启动相关分区，以及 modemst1/modemst2/fsg/fsc/persist 等设备唯一分区；根据实际设备确认分区存在。至少双读比较大小和哈希，离线保护备份。
2. 记录系统版本、当前槽位、更新合并状态与准确的 GKI 源码版本。实验参考 common 提交为 f4321180a3973d19b626b3eef51871199e4e1fac，不能直接假定适合其他系统版本。
3. 先构建基线，保持关键布局、CFI 和签名保护，再逐项增加功能。实验使用 Clang/LLVM14 和独立 pahole1.24；这不是对其他版本的强制要求。
4. 从本机获得厂商模块导入信息，比较独立构建的导出 CRC；BTF 布局变化需逐项解释。不能用自己分配给导入端的 CRC 反证头文件 ABI 正确。
5. 采用本机匹配的启动镜像封装方式，验证镜像头、内核架构、大小和分区容量。检查工具的具体输入格式请阅读源码。
6. 先临时启动，验证显示、相机、调制解调器、音频、Wi-Fi、Root、SELinux、模块和错误日志；再决定是否持久写入。
7. USB 网卡需要真实硬件验收。驱动能够加载只说明模块注册成功。

这里未发布刷机命令。实际刷入必须由操作者针对自己的设备和可恢复条件作出决定。不要清除温控、强卸载 permanent 模块或关闭 SELinux 来掩盖兼容性问题。
